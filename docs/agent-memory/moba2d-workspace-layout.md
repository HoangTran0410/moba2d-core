LAN netcode facts worth not re-deriving (measured 2026-08-28): a 5v5 snapshot is ~3.0KB and the stream ~90KB/s with encode+decode under 1ms/s — **bandwidth is not the lag source**, so viewport culling is the wrong axis (and culled != gone: `InterpolationBuffer.sample` leaves a unit missing from the newest snapshot alone, so omission is safe, but a client would hold a ghost forever without an explicit lost-sight state). Fog-of-war culling is the right axis and only for anti-maphack. Snapshots now send only changed units with a 1s heartbeat, and cooldowns only for champions a client actually plays. Items/gold **were** synced on 2026-08-28: the bag crosses as a `bag` event diffed in `discover` (and carried in the hello, since a diff only speaks on change), gold rides the snapshot tail beside `cds` for client champions only, buy/sell/swap go to the host with no local half, and item actives use `cast`/`rel`/`stop` with `row: 'item'`. **The trap that fell out of it, worth remembering**: the snapshot carries a stat's *composed* value, and the client used to store it into `baseValue` — safe only while a client's champion had no modifiers of its own. Real items broke that (a belt counted twice), so `ClientSession.setComposedValue` now inverts `value = ((base + baseBonus) * (1 + pctBase) + flat) * (1 + pct)` to place the base. Any future stat that crosses the wire must go through it, not through a plain `baseValue =`.
