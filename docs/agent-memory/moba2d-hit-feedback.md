On 2026-09-02 the "cảm giác trúng đòn" bundle landed in core (spec `docs/superpowers/specs/2026-09-02-hit-feedback-design.md`), left **uncommitted** for the user to review: `AttackableUnit.presentHit({amount,type,crit})` is the single door for a hit's look (CombatText + white body flash + crit spark + camera shake for the player), reached from host `takeDamage` and from `ClientSession`'s `dmg` handler; `takeDamage` grew a 5th `presentation?: { crit }` param (`takeDamageSignature.test.ts` now requires five names and five forwarded args); `dmg` net event has `c?: 1`; `Camera.shake/advanceShake/setShakeEnabled` with the offset applied inside `applyRenderOrigin` (Game.draw now always substitutes/restores, not only when alpha<1) so fog/minimap shake with the world; `moba2d.screenShake` pref in renderPreferences.ts served by both MatchConfigSources and a checkbox in SettingsTab "Hiển thị"; `render/hitFeedback.ts` holds the pure tables. The crit spark moved from BasicAttack into presentHit (owner = victim). **CombatText now says two numbers per object**: a *headline* (`recent`, hits coalesced within `HEADLINE_WINDOW_MS`=150ms of the group's first hit; size + crit style follow it) and a *total* (`amount`, drawn small with a `∑` prefix above the headline, only from the second group on). The user reported the merge hiding crit numbers; the alternatives (crit breaks merge; short merge window) were rejected for losing per-hit readability / raising object count.

**Traps:** the headless test worlds (`src/testing/world.ts`, `spellWorld.ts`) have a `player` getter that THROWS when unset — any presentation code that asks "is this the player" must go through `isLocalPlayer()` (try/catch) or 50+ combat tests fail. `drawAvatar` reads the player too (via `isAllied`), so a draw test must `game.setPlayer`. While all three packs (lol, dota, naruto) are linked, the pre-existing failure set is: matchConfigSource.contract ×2 (map list), shopSubject, preset.runtimePack, preset.customKitDefence, plus `tests/content/registry.test.ts` and `tests/game/slotObjects.test.ts`, the last two caused purely by the modified dev-link file `src/generated/installedPacks.ts` (A/B-verified by stashing only that file). Judge a core change by typecheck ×3 + check-seams + the touched tests, as before.

**Also landed 2026-09-02 (same uncommitted batch):** haptics (`src/game/input/haptics.ts`, pref `moba2d.haptics` in touchPreferences.ts, `feel(game, kind, trauma)` in AttackableUnit drives camera + vibration from one trauma number; the settings row is hidden without `navigator.vibrate`) and the kill feed (`src/game/combat/Announcer.ts` on `Game.announcer`; `EventType.ON_DIE` is now emitted once per death as the LAST thing in `die()` with `{unit, killer?, credit}`; `HudState.feed` + `KillFeed.vue` mounted in InGameHUD.vue; `ann` net event with `WireAnnouncement`; callout names in ENGLISH by the user's request — 'Tam sát' sounded flat to them: First Blood, Double/Triple/Quadra/Penta Kill, Shutdown, streak tiers Killing Spree(3)→Rampage→Unstoppable→Dominating→Godlike(7)→Legendary(8+); sentences stay Vietnamese). Layout after two rounds of feedback: TOP CENTRE like LoL, newest row on top, one `.kill-callouts` column with the banner *under* the rows (a fixed-position banner hid behind the stack); streak rows wear a fire accent so a run never looks like a kill; **occlusion budget** is the user's hard concern ("chết nhiều là UI che hết màn hình") — FEED_ROWS 3 (touch CSS hides the 3rd), FEED_TTL 6s, BANNER 2.2s, translucent rows, no infinite banner animation; `pointer-events: none` throughout. Specs: `2026-09-02-hit-feedback-design.md`, `2026-09-02-kill-feed-and-haptics-design.md`. A scratch Playwright script that forces kills via `window.__moba2d.scene.oScene.game.director.bots()[i].die({attacker: game.player, reviveAfter})` was the fastest way to screenshot the feed.

**Tab scoreboard (same day):** `HotKeys.TAB`, held not toggled (`Game.keyPressed/keyReleased`, blur releases it); browser Tab is swallowed by a capture `keydown` listener in GameScene because `SceneManager.keyPressed` passes no event; `hud.showScoreboard/setScoreboard/toggleScoreboard`; `HudState.scoreboard` built from `objectManager.objects` (killCredit==='champion', so LAN clients get it) + `HudState.clock`; `Scoreboard.vue` + `ScoreStrip.vue` (top-centre kills·clock·kills pill, the phone's way in). Scoreboard rows carry `ItemSlotDisplay[]` (via `buildItems(unit)`) so a hover/tap opens the owner's item card (stats + description) drawn inside Scoreboard.vue with the `.spell-info` classes (the HUD's own hover panel exists only in the desktop layout); `reviveAfter` seconds are painted over a dead champion's grey portrait. Layout traps found by the user on a real phone: team columns must be `auto-fit` (340px desktop / 300px touch) — a forced `1fr 1fr` overflowed in portrait; every grid level needs `min-width: 0` or the items column pushes past the team box; items fold 3×2 under 720px. Playwright in portrait: the `.orientation-hint` overlay intercepts taps — click its "Vẫn chơi dọc" button or call `hud.toggleScoreboard()` via `window.__moba2d`. **Trap:** a third corner button is impossible — `CORNER_BUTTON_BOX` must stay 104 or the recall circle lands on the expanded minimap at 667px (TouchLayout.test).
